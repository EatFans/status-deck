# Status Deck

Status Deck 是一个基于 ESP32 的开源桌面状态监控卡。它通过 BLE 与桌面客户端通信，将 AI 用量、API 额度、服务器状态、系统运行数据等实时显示在桌面小屏上。

这个项目的目标是做一个低成本、可复刻、可扩展的实体状态面板：不用频繁切换窗口，也能一眼看到当前工作流和基础设施的健康状态。

## 功能规划

- ESP32 设备端通过 BLE 接收桌面客户端推送的数据
- 实时显示 AI 用量、API 额度、账户余量或调用统计
- 显示服务器状态、延迟、CPU、内存、磁盘、服务可用性等指标
- 支持本机系统状态，例如电量、网络、CPU、内存、正在运行的任务
- 支持多页面/多卡片轮播展示
- 提供开放的数据协议，方便接入自定义数据源
- 适配常见 ESP32 开发板与小尺寸屏幕

## 桌面端分发

桌面端以单个 Go 可执行文件分发。运行时的状态栏图标由代码直接生成；打包时，同一份图标绘制逻辑会生成并嵌入 macOS 的 `.icns` 与 Windows 的 `.ico` 应用图标，因此用户不需要额外下载、放置或维护图标资源文件。

详细打包与开机自启说明见 [桌面端 README](./desktop/README.md)。

## 信息页面规划

Status Deck 将以多页面轮播为主要展示方式。用户可以通过自动轮播或设备侧按键切换页面；当出现重要异常时，设备应优先展示告警信息，而不是继续等待轮播。

| 页面 | 展示内容 | 目标 |
| --- | --- | --- |
| 页面 1：本机状态 | CPU、内存、磁盘、电量 | 快速了解电脑当前负载与资源余量 |
| 页面 2：AI 用量 | Codex 与其他 AI 服务额度、重置时间、调用统计 | 避免在工作中频繁打开额度页面 |
| 页面 3：服务健康 | 服务器可用性、延迟、资源占用与异常状态 | 及时发现基础设施问题 |
| 页面 4：开发流程 | Git 分支、未提交改动数、CI/CD 与部署状态 | 将代码与发布进度带到桌面上 |
| 页面 5：时间与专注 | 下一个日程、倒计时或专注计时 | 辅助安排当前工作节奏 |

告警页不是一个普通轮播页。当服务器不可用、磁盘接近满、系统持续高负载或 AI 额度低于阈值时，设备可以自动切换到对应告警页，并通过颜色、图标或提示音突出显示。

## 项目结构

```text
status-deck/
├── firmware/        # ESP32 固件代码
├── desktop/         # 桌面客户端
├── hardware/        # 硬件选型、接线验证和 PCB 工程
├── docs/            # 协议、硬件、接线和开发文档
├── tools/           # 辅助脚本
└── README.md
```

`hardware/` 目录会拆成两个阶段：

- `hardware/dev-board/`：开发板验证阶段，记录模块选择、购买清单、引脚分配、接线方式和测试结论
- `hardware/pcb/`：正式 PCB 阶段，放原理图、PCB 版图、BOM、Gerber 和生产相关文件

> 当前仓库处于初始化阶段，目录会随着固件、桌面客户端和硬件验证逐步补齐。

## 技术方向

- 设备端：ESP32、BLE、TFT/OLED/E-Paper 显示屏
- 电脑端：跨平台桌面客户端，负责采集数据并通过 BLE 下发
- 通信协议：轻量 JSON 信封，优先保证易调试和可扩展，详见 [BLE 通信协议](./docs/ble-protocol.md)
- 开发方式：优先支持 PlatformIO，后续可补充 Arduino IDE / ESP-IDF 指南

## 快速开始

项目还在早期设计阶段，建议先按下面的方向准备环境：

1. 准备一块支持 BLE 的 ESP32 开发板
2. 准备一块小尺寸显示屏，例如 ST7789、SSD1306 或电子墨水屏
3. 安装 PlatformIO 或 ESP-IDF 开发环境
4. 运行桌面客户端，并在配置文件中启用需要展示的数据源
5. 将固件烧录到 ESP32 后，通过 BLE 与桌面客户端配对

更完整的硬件清单、接线图、固件构建和桌面客户端使用说明会在后续版本中补充。
